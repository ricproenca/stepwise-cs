# Frontend — Cambridge 9618

## Tech Stack

- **Static HTML + vanilla JS** — no framework, no build step, no npm
- Pages are generated by the `/frontend-builder` Claude skill from `content/{slug}/*.md`
- Open `frontend/index.html` directly in any browser; no server required
- Deployment: drag `frontend/` to GitHub Pages, Netlify, or any static host

## Directory Layout

```
frontend/
├── assets/
│   ├── style.css          ← CSS custom properties (copy of design-system/style.css)
│   └── components.css     ← Component classes (copy of design-system/components.css)
├── index.html             ← Home page: hero + topic grid with AS/A Level filter
└── topics/
    └── {slug}/
        ├── index.html     ← Notes page (3-column: sidebar | content | key terms)
        ├── questions.html ← Questions page (filter by difficulty, reveal answers)
        └── glossary.html  ← Glossary page (search, letter nav, differentiators)
```

## Pipeline

Run stages in order. Never skip.

| Stage | Command | Output |
|-------|---------|--------|
| 0 (once) | `/bootstrap` | design-system files + frontend/assets/ |
| 1 | `/resource-collector [topic] [slug]` | resources/scraped/{slug}/ |
| 2 | `/content-creator [topic] [slug]` | content/{slug}/ |
| 3 | `/frontend-builder [topic] [slug]` | frontend/topics/{slug}/ |

## Design System

All design decisions come from `design-system/`. Reference these files in order:

| File | Purpose |
|------|---------|
| `design-system/style.css` | CSS custom properties — colours, typography, spacing, shadows |
| `design-system/components.css` | Component classes — `.card`, `.btn`, `.badge`, `.reveal`, etc. |
| `design-system/design-tokens.md` | AI-readable token reference for frontend-builder |
| `design-system/README.md` | Full brand guidelines (tone, visual foundations, iconography) |
| `design-system/svg-templates/` | Reference SVGs for flowchart, binary-diagram, memory-map, timeline, tree-diagram |

Every generated HTML page links to `/assets/style.css` and `/assets/components.css`.
No inline styles. No hardcoded colour values.

## Coding Standards

1. Use semantic HTML5 (`article`, `section`, `nav`, `aside`, `main`, `header`, `footer`).
2. All interactivity in vanilla JS — no frameworks, no external libraries.
3. ARIA labels on all interactive elements.
4. Mobile-responsive via CSS grid/flexbox from the design system.
5. No emojis in UI text.
6. Oxford English spelling (programme, recognise, organisation).
7. Keep it simple — no over-engineering. When hitting issues, identify root cause before fixing.
